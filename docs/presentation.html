Who are the ~800? The most likely answer is outsourced reviewers who handle identity checks and customer support, each with a license.

If so, three things follow

The bill grows with the contractor team

Every new reviewer adds about $240 a year. In a tool the client owns, an extra user costs almost nothing.

Power Apps' main selling point goes unused

Its strength is letting non-engineers build apps. Contractors only use apps; they don't build them.

Security has to be strict

Hundreds of outsiders see customer personal data. Any tool must limit what each person sees and log what they view.

This is an assumption. Confirm it by asking for the list of paid users by type (see appendix if it's wrong)1

The part of Power Apps worth paying for is its security, and Devin can rebuild what this client needs

1

The value is the controls, not the app builder

Power Apps decides who can see which records and fields, keeps an activity log, and applies company-wide data rules. Contractors don't use the app builder.

2

Devin built a working version of those controls

Each user sees only the records their role allows. Sensitive fields are masked or hidden. Approvals need a second person. Every change is logged.

3

New tools are then cheap to add

Each new tool reuses the same controls, so it's a short description and a test, not a new project.

4

What's left is running it, which still needs people

Hosting, backups, outside security testing, and a named owner, about half of one engineer's time.

Not worth rebuilding
  • Microsoft's 1,000+ ready-made integrations and its workflow automation
  • The drag-and-drop app builder
  • The feature-flag tool: buy an off-the-shelf product
Live demo: the same review queue seen by two different roles

Build with Devin if the data and users sit outside Microsoft, which is likely here

Build with Devin if
  • Most users are outside contractors (slide 1)
  • The data lives in the company's own database, not in Microsoft's (Dataverse)
  • The tools are simple: review queues, forms, approvals

Why this is likely the case here

  • A ~200-person Series C fintech runs its product on its own database. Power Apps is most likely reading that data, not storing it.
  • Startups at this stage pick simple, fast tools. 3 basic review tools look like a quick fix that grew, not a deep Microsoft commitment.
Stay on Power Apps if
  • Most data is stored in Microsoft's database (Dataverse)
  • The tools depend on Microsoft's automation and reporting (Power Automate, Power BI)
  • Most users are employees who build their own tools
  • No engineer can own a custom system
